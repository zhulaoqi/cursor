# Cursor Account Manager 每日明细落库（StarRocks）实施计划

## 1. 计划目标

本计划文档仅聚焦执行落地：
- 任务拆解
- 里程碑与工期
- 验收标准
- 风险、回滚与上线策略

技术细节（架构、DDL、接口）见：`docs/starrocks-daily-sync-tech-design.md`。

---

## 2. 交付范围

本次交付应包含：
1. StarRocks ODS + DWD 表上线。
2. 每日同步任务（可手动触发、可调度触发、可重跑失败账号，支持动态账号池）。
3. SQLite 任务运行日志（run / stage / account 三级）。
4. Web 监控页（今日状态、开始/结束时间、阶段日志、失败账号）。
5. 告警与补偿机制。

---

## 4. 测试与验收清单

## 4.1 功能验收

- [ ] 指定日期全量同步成功。
- [ ] 指定 run_id 可查询完整阶段日志。
- [ ] 失败账号可定向重跑并回填结果。
- [ ] Web “今日同步”页面数据正确且刷新正常。
- [ ] 运行中新增账号不影响当前 run，且在下一次 run 生效。
- [ ] 可对新增账号执行手动补拉（不需要等待次日）。

## 4.2 数据验收

- [ ] `ODS` 行数与解析输出行数一致。
- [ ] `DWD` 行数与业务口径一致（去重后）。
- [ ] 同一天重跑后结果一致（幂等验证）。

## 4.3 稳定性验收

- [ ] 异常网络场景下具备重试行为。
- [ ] 单账号异常不阻断整批执行。
- [ ] 告警在失败/超时时按预期触发。

---

## 5. 风险清单与应对

1. 上游 API 抖动或风控  
   - 应对：并发限流 + 指数退避 + 失败补跑。

2. StarRocks 写入慢或暂时不可用  
   - 应对：任务失败落日志，保留 staging 数据，恢复后重跑。

3. 字段映射变更导致解析异常  
   - 应对：解析容错、字段版本化、异常账号隔离。

4. 调度器故障导致漏跑  
   - 应对：每日巡检任务 + 手工 `sync-daily` 补跑通道。

5. 账号池频繁变化导致口径不一致  
   - 应对：run 启动冻结账号快照；报表按 run_id 展示快照账号数与新增账号数。

---

## 6. 回滚与应急预案

- 场景A：当日任务失败  
  - 操作：定位失败阶段 -> 修复后重跑同一 `biz_date`。

- 场景B：DWD 口径错误  
  - 操作：按日执行 `DELETE + INSERT SELECT` 重建。

- 场景C：调度异常  
  - 操作：手动执行 `python -m cam sync-daily --biz-date <date>`。

- 场景D：部分账号失败  
  - 操作：执行 `sync-retry` 仅重跑失败账号。

上线前必须全部满足：
- [ ] 测试与预发布通过（含幂等重跑）。

- [ ] 灰度观察无阻断问题。
